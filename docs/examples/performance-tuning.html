Performance Tuning

DnsForwarder is designed for high throughput and low latency. This guide explains how to optimize performance for production deployments.

1. Enable Caching

Caching dramatically reduces upstream load and improves response times. 

{
  "Caching": {
    "Enabled": true,
    "TtlSeconds": 300,
    "MaxEntries": 20000
  }
}

2. Use Fast Upstream Resolvers

Choose resolvers with low RTT (round‑trip time). Cloudflare (1.1.1.1) and Quad9 (9.9.9.9) are common choices.

3. Minimize Regex Rules

Regex rules are powerful but slower than prefix/suffix/wildcard rules. Prefer:

  • *.example.com instead of ^.*example\.com$
  • *ads* instead of .*ads.*

4. Use Wildcard Hosts for Local Overrides

Static host overrides via StaticDnsClient are extremely fast. Wildcard hosts allow broad overrides without performance cost.

5. Benchmark Your Configuration

Use BenchmarkDotNet to measure rule engine performance: 


public class RuleEngineBenchmarks
{
    private readonly RuleEngine _engine;

    public RuleEngineBenchmarks()
    {
        _engine = CreateEngineWithRules();
    }

    [Benchmark]
    public void MatchDomain()
    {
        _engine.Match("foo.example.com", "bench");
    }
}

6. Reduce Logging in Production

Debug logging is useful during development but slows down high‑volume servers. 


"Logging": {
  "Level": "Warning"
}

7. Run on Modern .NET

DnsForwarder benefits from improvements in .NET 8/9/10, especially in networking and GC.

8. Use SSD or tmpfs for Large Blocklists

If loading very large blocklists, ensure the filesystem is fast to reduce startup time.

9. Tune OS Networking

Linux sysctl parameters can improve UDP performance: 


sudo sysctl -w net.core.rmem_max=26214400
sudo sysctl -w net.core.wmem_max=26214400
sudo sysctl -w net.ipv4.udp_mem="65536 131072 262144"

10. Run Behind a Local DNS Cache

Pairing DnsForwarder with systemd‑resolved or Unbound can reduce upstream traffic.
